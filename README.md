# Debate bot

Telegram-тренер по дебатам на греческом языке. Node.js 24, Express,
Telegram webhook и Groq (`openai/gpt-oss-120b`). История разговоров хранится
в памяти и сбрасывается при перезапуске.

## Автоматический деплой

Push в `main` запускает `.github/workflows/deploy.yml`. Для pull request
выполняются только тесты и аудит. Деплой также можно запустить вручную во
вкладке Actions: **Deploy debate bot → Run workflow**, ветка `main`.

Нужны три repository secrets:

- `DEPLOY_SSH_KEY` — приватный SSH-ключ пользователя deploy целиком.
- `TELEGRAM_TOKEN` — токен бота.
- `GROQ_API_KEY` — ключ Groq.

Адрес назначения: `deploy@185.183.157.185:22`. Ключ SSH сервера закреплён
в `deploy/known_hosts`; HTTPS проверяется по публичному сертификату
`deploy/webhook.pem`. Приватный TLS-ключ хранится только на сервере.

Workflow устанавливает зависимости из lock-файла, выполняет тесты и аудит,
передаёт код и конфигурацию по SSH, устанавливает зависимости от deploy,
проверяет доступ к Telegram/Groq и переключает `/srv/debate-bot/current`
на новый каталог релиза. Служба `debate-bot.service` перезапускается через
ограниченную sudo-команду. `/healthz` должен подтвердить регистрацию webhook
и SHA текущего коммита. Дополнительно GitHub runner проверяет HTTPS снаружи.

Если активация не удалась, скрипт возвращает предыдущий релиз. При неудаче
первого запуска он останавливает службу и пытается восстановить прежний
webhook (для старого webhook с неизвестным самоподписанным сертификатом
нужно ручное восстановление). Неудачная внешняя проверка из runner помечает
workflow как failed; уже прошедшая активация в этом случае сохраняется.

В `/srv/debate-bot/deployment.json` сохраняются SHA успешно активированного
коммита и ссылка на запуск GitHub Actions. `last-ci-run.json` содержит
результат workflow, если его SSH-доступ удалось настроить.
Релизы хранятся в `/srv/debate-bot/releases`, их `.env` доступны только deploy.
Старые релизы сохраняются для отката; при ротации секретов их `.env` также
следует удалить после окончания периода отката.

## Сервер

Первичная настройка от root: `bash deploy/bootstrap.sh` из корня репозитория.
Пользователь deploy и ограниченный обработчик `/usr/local/sbin/debate-deploy-admin`
должны быть созданы заранее. Обычные push не меняют root-конфигурацию сервера.
Изменения unit или Nginx применяет администратор отдельно.

Webhook: `https://185.183.157.185/telegram`. Сертификат для IP передаётся
Telegram при регистрации; запросы проверяются по секретному заголовку.
Токен бота не включается в URL и журналы. Приложение слушает только
`127.0.0.1:3000`, HTTPS обслуживает Nginx на порту 443.
Служба включена в автозагрузку и перезапускается при аварийном завершении.
Периодического keep-alive больше нет.

Самоподписанный сертификат действует до **20 сентября 2027 года**.
До истечения срока администратор должен обновить сертификат, файл
`deploy/webhook.pem`, перезагрузить Nginx и перезапустить бота для передачи
нового сертификата Telegram. Старый хостинг следует остановить, чтобы его
процесс не зарегистрировал прежний webhook при перезапуске.

Команды от deploy:

```sh
sudo -n /usr/local/sbin/debate-deploy-admin bot-status
sudo -n /usr/local/sbin/debate-deploy-admin bot-logs
sudo -n /usr/local/sbin/debate-deploy-admin bot-restart
sudo -n /usr/local/sbin/debate-deploy-admin update-system
```

## Локальная проверка

```sh
npm ci --ignore-scripts
npm run check
npm test
```

Тесты используют подставные API, не отправляют сообщения и не изменяют
рабочий webhook. Для запуска нужны `TELEGRAM_TOKEN`, `GROQ_API_KEY`,
`WEBHOOK_URL` и, при самоподписанном сертификате, `WEBHOOK_CERTIFICATE`.
В продакшене workflow также задаёт `REVISION`, `HOST` и `PORT`.
Не добавляйте `.env`, файлы с токенами или приватные ключи в Git.
